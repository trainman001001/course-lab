# 毕设题目设计（E 线）：从「面向证券交易的多智能体系统」到可开题的计算机本科课题

> **性质**：选题论证与设计稿，供指导教师与指导组拍板；尚未定名、尚未生成开题报告。
> **合规声明**：本文为毕业设计选题方案，**不构成任何投资建议，不涉及证券投资咨询业务**；文中所有标的、行情、条款与数值均为虚构教学样例，不对应任何真实证券、真实账户或真实交易。
> **拟定日期**：2026-11-05　**维护者**：黎方正

## 零、先回答「如何成为毕业设计课题」

**一句话结论**：按字面做不了，但**降维后是可执行度高、难度中等、且与 D 线同构的好题目**。

关键动作不是加功能，而是**换掉题目的四个要素**：把「证券交易」从目的降为**场景载体**，把「能不能赚钱」换成「决策过程能不能核验」。这样课题就从「量化策略 / 智能投顾」变成「多智能体协同过程的可解释、可回放、可对照评测」——一个标准的计算机本科毕设。

| # | 换什么 | 从 | 到 |
|---|---|---|---|
| ① | 研究对象 | 交易执行与策略收益 | 多角色决策过程、分歧发现与证据链 |
| ② | 场景 | 真实市场 / 实盘 / 实时行情接口 | 固定历史快照 + 虚构标的 + 离线样例任务 |
| ③ | 产出 | 买卖信号、下单、目标价、仓位 | 结构化观点卡 + 类型化分歧提示 + 人工确认 + 决策档案 |
| ④ | 判据 | 收益率、胜率、夏普、模拟盘盈亏 | 分歧发现率、误报率、依据可回溯率、重跑一致率、人工负担 |

**第 ④ 步是分水岭**：只要验收指标里还留着收益类指标，题目就仍然是策略题，评审一定会追问「回测有没有未来函数、交易成本、幸存者偏差、过拟合」，而这些都不是计算机本科毕设能答好、也不该由它来答的问题。

## 一、为什么按字面做不行

| 风险 | 具体表现 | 后果 | 本方案的处理 |
|---|---|---|---|
| 合规风险 | 输出买入/卖出建议、目标价、仓位；接券商或行情接口做自动下单；对外发布或面向真实用户 | 证券投资咨询需持牌；实盘/代客/荐股均越界；学院与答辩都会亮红灯 | 全部标的与数值虚构，立场只到抽象标签；不接任何接口；不发布上线；报告首页标注「不构成投资建议」 |
| 学术不可证伪 | 策略收益由行情支配，无法归因于「多智能体」；LLM 输出随机，回测不可复现 | 结论不可归因、不可重跑，「演示即成果」 | 预置分歧评测集 + 三组公平对照 + 录制回放；判据全部为过程指标 |
| 工作量失控 | 真实交易系统涉及订单管理、风控、撮合、账户、低延迟、合规审计 | 本科做不完，且做完了也不是计算机毕设核心能力 | 整个执行层砍掉，只保留「提案—分歧—确认—档案」流程 |
| 数据合规 | 行情数据授权、Level-2 版权、公告与舆情来源、账户数据 | 数据来源不可核对，或需授权 | 固定快照自带 `snapshot_id` 与哈希；优先合成数据；若用公开数据须注明来源与用途限制，不用于生成建议 |
| 表述风险 | 题名出现「交易」「策略」「智能投顾」「选股」「系统」 | 评委未读正文就先入为主 | 命名口径改用「决策场景」「样例任务」「协同原型」「可核验交付」 |

## 二、降维后的课题定位

**研究对象**：多智能体协同的**决策过程与证据链**（角色协议、分歧判定、人在回路、可回放档案），不是证券机理、不是行情预测、不是交易执行。

**可证伪的研究问题**：在固定快照的虚构决策样例上，采用「角色化多智能体提案 + 类型化分歧检测 + 人在回路确认」的协同编排，是否比单 Agent 串行与纯人工表单**发现更多预置分歧**（发现率更高）、**依据更可回溯**，且**不显著增加人工负担**？

**定位口径**：可运行的教学 / 科研原型与过程证据，不替代任何投研流程，不面向真实用户，不以真实市场表现为目标。

**与 D 线的关系**：**同一骨架，换场景**。D 线（多智能体冶金工程设计协同）的工件 → E 线的观点卡；C1–C4 冲突 → D1–D4 分歧；对照报告 → 决策档案；主路径、验收阻断项、可复现方案几乎可整体复用。**唯一但致命的差别是 E 线多了一层金融合规红线，且必须把收益从判据里彻底删掉。**

### 主推题名

> **《不预测涨跌，只核验过程：面向证券决策场景的多智能体可核验协同原型的设计与实现》**
> 副题：「没有回放，就还是演示」——从多角色观点卡、分歧提示到人工确认与对照实验

### 备选题名

| 编号 | 题名 | 侧重 |
|---|---|---|
| A | 把「多空分歧」跑成对照实验：证券决策场景多智能体分歧检测与可解释提示原型 | 最聚焦，工作量最可控，适合能力中等的学生 |
| B | 从行情快照到决策档案：面向证券场景的多智能体可回放协同工作台 | 偏工程与交付，适合工程化能力强的学生 |

## 四、开题三问与书面回答（沿用指导组要求）

| 三问 | 书面回答（锁定口径） |
|---|---|
| ① 各 Agent 的输入与输出分别是什么 | 输入＝固定快照（`snapshot_id` + 数据时点 + 哈希）、预置条款/公告库、共享工作区当前版本、上一回合分歧与待定项清单；输出＝一份**结构化观点卡 JSON**（立场标签、claim 参数表、依据条款、快照 ID、版本号、模型元信息），落盘而非停留在对话。四类角色各有独立输入视图、模板与日志，不得只换提示词人设。 |
| ② 分歧与待定项如何被发现，如何交由人或仲裁处理 | 由**类型化规则 D1–D4** 在结构化 claim 上确定性计算得出（见第七节），不依赖模型自述；每条分歧输出「命中规则 + 双方 claim 与 clause_ref + 快照 ID + 版本」。处置统一交**工作台上的真人**做确认 / 驳回 / 批注；可给确定性优先级建议，**不设仲裁 Agent**，以保证链路完整可回放。 |
| ③ 用哪几套样例证明闭环成立 | 8–12 个虚构标的决策样例任务（固定快照 + 背景材料），每套含四类角色观点卡模板、≥12 条人工埋点分歧（D1/D2/D3 各 ≥4）、≥6 组相似论证对及 `golden.json` 标准答案；以三组对照实验证明「提案—分歧/相似提示—人工确认—决策档案」闭环成立。 |

## 五、模块分解（M0–M8）

| 模块 | 内容 | 关键约束 |
|---|---|---|
| M0 | 场景与红线锁定 | 虚构标的、固定快照、不构成投资建议声明；开题即写死，中途不得扩范围 |
| M1 | 快照与条款层 | 行情/公告/条款固定快照，`snapshot_id` + 数据哈希；不接实时接口、不拉取未授权数据 |
| M2 | 角色 Agent 与观点卡 | 四类角色、工件 schema、回合编排、独立输入输出与日志 |
| M3 | 类型化分歧判定 | D1–D4 规则集，确定性计算，与 LLM 调用解耦，可脱模型重算 |
| M4 | 相似论证检索与解释 | 结构化字段相似度 Top-k；解释 = 命中规则 + 双方依据 + 快照，禁止模型自述 |
| M5 | 人在回路工作台 | 确认 / 驳回 / 批注，处置留痕；不设 LLM 仲裁；面板若展示行情，遵循 A 股惯例涨红跌绿、金额用 ¥，且只展示合成快照 |
| M6 | 决策档案与回放 | 每回合 JSONL、版本链、录制回放 fixture、`mock_llm` 兜底、README 双命令 |
| M7 | 对照实验与指标 | G1/G2/G3 三组、公平性控制、7 项过程指标、≥3 个可解释用例 |
| M8 | 教学产品化轻量出口（可选） | 把「决策档案」降维成课程里「可核验交付层」的教学案例，呼应三级台阶；**止步教学语境，不做产品、不对外发布** |

## 六、角色与观点卡 schema

| 角色 | 职责 | 典型 claim（均为虚构样例参数） |
|---|---|---|
| 基本面 / 估值 | 给出估值区间与财务约束 | 估值区间、盈利增速假设、口径说明 |
| 量价 / 技术面 | 给出趋势与波动描述 | 波动区间、量能区间、形态标签 |
| 风险条款 / 合规 | 只查预置条款一致性，不做风控决策 | 集中度上限、条款互斥对、披露要求 |
| 事件 / 公告 | 基于固定公告快照给依据 | 公告条目编号、事件类型、时点 |

```
opinion_card = {
  task_id, role, card_id, version, parent_version,
  snapshot_id,             // 固定快照：数据时点 + 数据哈希
  stance,                  // 抽象立场：支持 / 反对 / 存疑
  claims: [ { key, unit, value, range: [low, high], clause_ref, evidence_ref } ],
  rationale,               // 依据：条款号 / 公告条目 / 快照片段
  created_at,
  llm_meta                 // model, version, temperature, seed, prompt_hash
}
```

**合规硬约束**：`stance` 只能是抽象立场标签；`claims` 中所有数值均为虚构样例参数；**工件中不得出现买入、卖出、目标价、仓位、下单指令或任何可执行投资建议**。条款库与公告库为人工预置的虚构条目，编号可核对。

## 七、分歧类型化定义（D1–D4）

| 编号 | 类型 | 判定条件 | 处置 |
|---|---|---|---|
| D1 | 同标的异立场 | 不同角色对同一虚构标的给出不同 `stance`，且置信区间不相交 | 生成分歧项，附双方观点卡与依据，交人工确认 |
| D2 | 区间不相交 | 两角色对同一 `key` 的 `range` 交集为空 | 同上 |
| D3 | 条款互斥 | 双方 `clause_ref` 指向预置互斥条款对 | 同上 |
| D4 | 口径 / 时点不一致 | `snapshot_id` 不同、复权或单位口径不同且未换算 | 记为「待定项」，不判分歧，先要求澄清 |

**解释输出模板**（固定格式，非自由文本）：

```
分歧 D2 @ claim: valuation_range
  估值角色: [18, 24]    依据 V-04   快照 SNAP-003   卡片 C-估值-v2
  风险角色: [<= 16]     依据 R-11   快照 SNAP-003   卡片 C-风险-v1
  判定: 区间交集为空 -> 命中规则 D2
  处置: 交人工确认（确认 / 驳回 / 批注），不设仲裁 Agent
  声明: 以上数值为虚构样例参数，不构成投资建议
```

分歧判定全部为确定性规则计算：**给定同一组观点卡，不调用模型也能重算出完全相同的分歧集合**。这是「可解释」「可回放」「重跑一致率」三项要求共同的前提。

## 八、样例任务包、评测集与对照实验

### 8.1 样例最小规格

| 项 | 规格 |
|---|---|
| 样例任务 | 8–12 个虚构标的决策任务，固定快照 + 背景材料 |
| 观点卡模板 | 四类角色各 1 套，字段与 schema 一致 |
| claim 条目 | 每套 ≥20 条，覆盖四类角色 |
| 埋点分歧 | 每套 ≥12 条，D1/D2/D3 各 ≥4，写入 `golden.json` |
| 相似论证对 | 每套 ≥6 组，标注命中字段 |
| 标准答案 | `golden.json`：分歧清单、类型、涉及卡片、建议处置 |
| 数据 | 全部虚构或明确标注来源的公开历史快照；不使用账户数据，不用于生成建议 |

### 8.2 三组对照

| 组别 | 编排方式 | 说明 |
|---|---|---|
| G1 | 多角色协同（本系统） | 四角色并行提案 + 类型化分歧检测 + 人工确认 |
| G2 | 单 Agent 串行 | 同一模型依次扮演四角色，串行产出观点卡，共用判定模块 |
| G3 | 纯人工表单 | 结构化表单人工填写，无 LLM 生成，共用判定模块 |

**公平性控制**：同一套样例、同一基座模型、同一 token / 回合预算上限、同一 `golden.json`、同一人工评审者；三组只变编排方式，分歧判定模块三组共用。

### 8.3 可解释用例（≥3）

E1（D1 同标的异立场）、E2（D2 区间不相交）、E3（D3 条款互斥）各一个，建议再加 E4（D4 口径误报被人工驳回）。每个用例须能从原始观点卡重算复现，并附人工确认记录与「不构成投资建议」标注。

## 九、评价指标（全部为过程指标）

| 指标 | 定义 |
|---|---|
| 分歧发现率 | 检出预置分歧数 / 预置分歧总数，按 D1/D2/D3 分列 |
| 误报率 | 非预置分歧被报出的条数 / 总报出条数 |
| 依据可回溯率 | 每条提示可追溯到 `clause_ref` / `snapshot_id` / 卡片版本的比例 |
| 相似论证命中率 | Top-k 中命中预置相似对的组数 / 预置相似对总数 |
| 重跑一致率 | 同输入重跑，分歧集合与决策档案一致的比例 |
| 人工负担 | 确认回合数、人工修改次数、端到端耗时 |
| 提示采纳率 | 人工采纳的提示数 / 提示总数 |

**明确排除**：收益率、胜率、夏普比率、最大回撤、模拟盘盈亏、策略有效性——**一律不作为验收指标，也不写入结论**。

结论表述须克制：若 G1 在发现率与依据可回溯率上优于 G2/G3 且人工负担不显著上升，则支持协同编排有效；**若差异不显著，须如实报告并分析原因，不得强行宣称优势**。

## 十、红线与验收阻断项

### 10.1 红线（证券场景专属 + 沿用四线通用红线）

1. 不接券商、行情实时接口，不做实盘或模拟盘自动下单，不面向真实用户、不发布上线；
2. **不输出买入/卖出/目标价/仓位等可执行投资建议**，所有标的与数值为虚构样例，报告与演示首页标注「不构成投资建议」；
3. 不以收益类指标验收，不声称策略有效、不声称预测能力；
4. 不从事证券投资咨询，不代客理财，不使用未授权数据源，不编造行情数据；
5. 不设 LLM 仲裁，不把模型自述当作可解释证据；不编造文献、DOI、卷期；
6. 论文与答辩须**专节**写清「多智能体做了什么 / 人做了什么 / 红线没做什么」。

### 10.2 验收阻断项（仿 D 线，第 ⑤ 条为本线专属）

**出现任一项即验收不通过：**

1. 原型按 README 跑不通，或「发布任务 → 多 Agent 出观点卡 → 分歧/相似提示 → 人工确认 → 决策档案」主路径断裂；
2. `<2` 个角色 Agent，或仅换人设无独立输入输出与日志；
3. 无分歧 / 协商可回放记录；
4. 无 ≥1 组多智能体 vs 单 Agent/纯人工对照用例；
5. **把实盘、自动下单、收益或策略有效性写成已完成，或输出可执行投资建议**（本线专属，一票否决）；
6. 使用未说明来源的行情数据，或样例中出现真实标的与实际买卖建议。

### 10.3 三分责任表

| 多智能体做了什么 | 人做了什么 | 明确没做什么 |
|---|---|---|
| 按角色协议产出结构化观点卡，附条款与快照依据 | 编写任务书、条款库、公告库与虚构快照 | 未做行情预测、未生成买卖建议 |
| 并行提出可能不相容的 claim，形成待比较方案集 | 埋点预置分歧、维护 `golden.json` | 未接券商接口、未做实盘或自动下单 |
| 输出可由规则重算的分歧解释与版本链 | 对每条分歧确认/驳回/批注，审定对照结论 | 未声称策略有效、未用收益指标验收 |
| 全程留痕（prompt、输出、工具调用、卡片版本） | 复核回放一致性，签署验收与合规声明 | 未让模型充当仲裁者，未把自述当证据 |

## 十一、可执行度、难度与适用学生

| 维度 | 判断 |
|---|---|
| 可执行度 | **高（4/5）**：纯离线、虚构样例、无需授权数据、无需接口、笔记本可开发 |
| 难度 | **中等，设计型而非算法型**：难点在评测体系与证据链，不在编码量 |
| 隐形难点 | ① 分歧的形式化（D1–D4）；② LLM 随机性与可回放冲突；③ 对照公平性；④ **范围克制**（学生最容易忍不住加「回测收益曲线」，一加就变味） |
| 风险等级 | 中高，**合规表述风险 > 技术风险** |
| 适合学生 | 协议设计、工程化、写作与边界论证能力强；**不适合**想做量化策略、模型训练或「炒股 AI」的学生 |
| 可伸缩性 | 下限：规则 Agent + 8 个样例 + 录制回放；上限：条款 RAG 依据检索、更细分歧类型、更完整的量化对照 |
| 与 D 线共用 | 代码框架、评测规范、可复现方案、验收表几乎可整体复用，开发成本显著低于另起炉灶 |

> 若学生坚持想做「量化」，应**另开一条线**：公开数据 + 严格回测协议（含交易成本、未来函数检查、样本外划分）+ 不含 LLM 荐股的传统量化工程题；但那与多智能体无关，且需确认数据授权，**不建议混在本题**。
