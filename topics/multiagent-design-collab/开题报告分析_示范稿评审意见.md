## 一、先厘清评价口径：这不是成品，是一张「命题卡」

文首说明已经把性质写死：

> 本文件为指导教师用模板/示范稿，学生须按学院与指导组要求改写、核实并补全。文中以 Suggested: 起首的句子为示范性补写，非锁定结论；标注【待填】【待补】【待学院节点回填】处须学生自行填写。正式内容口径以指导组锁定题名、阻断项与开题三问为准。

因此**不能用「成品开题报告」的尺子去打分**。全文有 6 处封面【待补/待填】、4 处进度【待学院节点回填】、`Suggested:` 示范句 6 处、「参考文献线索」整节为空——这些不是疏漏，是刻意留白。

正确的评价问题是两个：

1. **作为约束骨架**：它能不能把学生钉在正确的方向上，防止本科毕设最常见的翻车？→ 结论：**非常能，是这份稿子最大的价值**。
2. **作为可直接提交的开题报告**：还差什么？→ 结论：**差距较大，缺的不是字数，是「可计算、可复现、可证伪」的三块地基**。

一句话总评：**这是一份优秀的「防翻车约束」，但是一份不及格的「开题报告成品」。** 两者不矛盾，因为它本来就只是前者。

## 三、骨架拆解：三问 → 内容 → 验收的可追踪链

这份稿子真正的内功，是三处「钉死项」彼此咬合，形成闭环：

| 开题三问 | 对应研究内容 | 对应验收阻断项 |
|---|---|---|
| ① 各 Agent 的输入与输出分别是什么 | （1）角色智能体与协议：工艺 / 热工 / 物料 / 标准，职责边界、消息与工件格式 | ② `<2` 个角色 Agent，或仅换人设无独立输入输出与日志 |
| ② 冲突与待定项如何被发现，如何交由人或仲裁 | （2）共享工作区、版本与待定项看板；（3）可解释冲突/相似提示；（4）人工确认闭环 | ③ 无协商/冲突可回放记录；① 主路径断裂 |
| ③ 用哪几套样例工程证明闭环成立 | （5）2–3 套虚构、结构完整的冶金设计样例 | ④ 无 ≥1 组「多智能体 vs 单 Agent/纯人工」对照；⑤ 把 CAE/DCS/真实出图写成已完成 |

主路径也固定成一句话：

> 发布任务 → 多 Agent 出片段 → 冲突/相似提示 → 人确认 → 对照报告（任一环节缺失即主路径断裂）

**这套「三问—内容—阻断项」三段式，比多数本科开题报告里的「研究内容罗列」高一个层级**：它把「做完了」变成可判定的二元条件，而不是答辩现场靠口才解释。建议把这层设计完整保留到正式开题报告，并作为整个题库的通用模板。

## 四、值得肯定的五个亮点

1. **开题三问直击多智能体毕设的三大死法**：Agent 只是换人设、冲突靠嘴说、没有可证明的闭环。三问分别封死这三条路。
2. **验收阻断项写成「出现任一项即不通过」**，且 ⑤ 明确禁止把 CAE / DCS / 真实出图 / 工业可用效果写成已完成——与 A/B/C 三条线共用的红线方法论完全一致。
3. **强制对照实验**（≥1 组多智能体 vs 单 Agent/纯人工、≥3 个可解释用例）：把「AI 有没有用」变成可证伪问题，拒绝「演示即成果」。
4. **角色划分有真实矛盾支撑**：工艺 / 热工 / 物料 / 标准四专业并行，对应「版本并行、约束交叉、冲突发现滞后」，不是凭空造场景。
5. **论文与答辩须专节写「多智能体做了什么 / 人做了什么 / 红线没做什么」**：这是成熟的人机责任边界要求，比泛泛写一句「人在回路」硬得多。

## 五、硬伤与风险（按严重度排序）

### 5.1 【致命】「冲突」没有可计算的定义

全文把「冲突与相似的可解释提示」当作核心贡献，却从未定义什么叫冲突。后果是：

- 冲突检测只能靠 LLM 自由判断 → 「可解释」退化为「让模型解释自己」；
- 没有 ground truth → 发现率、误报率、对照实验全部无法计算；
- 「禁止黑盒演示式通过验收」写成了一句禁令，却没给实现抓手。

**补丁**：把工件限定为结构化参数表，冲突定义为类型化规则（见第九节），解释输出 = 命中的规则编号 + 双方证据片段 + 依据条款，而非模型自述。

### 5.2 【致命】LLM 随机性与「可回放 / 按 README 跑通 / 对照可复现」互相打架

阻断项 ① 要求按 README 跑通、③ 要求可回放记录，但多 Agent 多回合调用天生不确定。学生最容易在答辩现场翻车的就是「昨天跑得出来，今天跑不出来了」。

**补丁**：固定模型版本与 `temperature=0`/seed；每回合 prompt / 输出 / 工具调用落盘 JSONL；提供「录制回放」fixture 与 `mock_llm` 开关，让 README 在无网、无 API 经费环境同样能跑通主路径。

### 5.3 【高】样例工程「虚构、结构完整」缺最小规格

「2–3 套虚构样例」没有规格，就没有标注，没有标注就没有评测集，对照实验的「多智能体更好」无从判定。

**补丁**：每套样例强制包含任务书、4 类角色工件模板、≥12 条人工埋点冲突（三类各 ≥4）、≥6 组相似方案对、一份 `golden.json` 标准答案。冲突发现率才有分母。

### 5.4 【高】「仲裁」含义含糊，与可回放要求冲突

三问②与内容（2）都写「交由人或仲裁处理」，但没说仲裁是谁。若设「仲裁 Agent」，其 LLM 决策将成为不可回放的隐式环节，直接顶到阻断项 ③。

**补丁**：明确「仲裁 = 工作台上的**人**（确认 / 驳回 / 批注）」；若需自动优先级，只能是确定性规则（如标准角色 > 工艺 > 热工 > 物料）且仅作建议，最终仍由人确认。不设仲裁 Agent。

### 5.5 【高】对照实验只有数量、没有指标与公平性控制

≥1 组对照，但「好」怎么衡量？不定义指标，对照就退化成两段演示视频；不控制变量，结论会被质疑「只是多花了算力」。

**补丁**：定义冲突发现率、误报率、人工修改次数、回合数/耗时、提示采纳率、重跑一致率；对照须同样例、同基座模型、同等 token/回合预算，只变「协同编排方式」。

### 5.6 【中】研究现状实际是空节，参考文献线索节无示范格式

全节 4 段都是方向名 + 【待补】，0 篇可核对文献。「禁止编造 DOI、卷期或伪引文」这条要求写得很好，但没给 1–2 条格式样例，学生反而容易凭空造。建议锁定 5 类锚点文献（多智能体协作框架 / 人在回路 / PLM 一致性维护 / 设计冲突检测 / 案例检索 CBR），按学院格式给示范条目，再要求 ≥15 篇真实文献。

### 5.7 【中】缺三节与一张图：研究难点、可行性分析、技术路线图

现稿八节覆盖标准体例，但「难点 / 可行性 / 方法学」缺位。评审最常问的「关键问题是什么、你凭什么做得完」没有落点。建议补一张技术路线图，并把「冲突形式化」与「可复现性」明写为两个关键难点。

### 5.8 【中】成本、依赖与离线兜底未写

多 Agent 多回合调用商用 API 涉及费用、限流、网络；本科毕设无经费保障。建议补「规则 Agent + LLM Agent 混合」与 mock 兜底，把「按 README 跑通」从依赖外部服务变成依赖仓库内资产。

### 5.9 【体例】格式硬伤（对成品提交而言）

0 张表格、59 段全 Normal、无目录页码、封面 6 处 + 进度 4 处待回填、指导教师「黎方正【确认】」是唯一已确认字段。作为示范稿无妨，直接提交会被学院格式审查退回。文字里的「钉死项」应表格化，变成可逐行核对的证据：开题三问对照表、角色 I/O 表、冲突类型表、样例规格表、对照指标表、进度表、红线三分表。

## 六、与既有三条毕设线的关系

| 线 | 题目 | 研究对象 | 共同方法论 | 与 D 的可迁移点 |
|---|---|---|---|---|
| A | 虚拟电厂—柔性冶炼负荷的绿电调度仿真与智能推荐原型 | 能源调度的物理过程 | 离线仿真、可解释推荐、对比实验、不接真实电网/DCS | 「可解释推荐」的证据呈现方式、红线话术 |
| B | 回转窑—矿热炉关键参数联动调控的仿真与可视化原型（AI 增强） | 工艺参数联动的物理过程 | 代理模型、规则蒸馏、对比实验指标定义、SHAP、轻量 RAG | **轻量 RAG 调专利/方案条文作依据**，可直接迁移给 D 的「标准角色 Agent」做条款依据检索 |
| C | 把「四张图」跑成流水线：数智校园数据基座「一数一源一责」可核验交付原型 | 数据流水线的可核验交付 | 回读核验、交叉组抽查、责任到人、不编造引文 | **「可核验交付层」思想几乎可直接复用**：让工作台每条冲突提示都能从工件原始版本重算复现，甚至让别组抽查别组的对照报告 |
| **D** | **面向冶金工程设计任务的多智能体协同原型系统** | **设计协作流程本身（LLM/多智能体为研究对象）** | 主路径固定、验收阻断、对照用例、红线专节 | — |

**D 的独特定位**：四条线里，A/B 面向冶金工艺的物理过程（要建模、要数值仿真），C 面向数据流水线（要湖仓、要口径），**D 是唯一以「LLM 多智能体本身」为研究对象、几乎没有数值计算、全靠协议设计与证据设计立住的题目**。

这决定了两件事：

- **难度来源完全不同**：D 不难在算法，难在「评测体系设计」——冲突怎么算、结果怎么复现、对照怎么公平。学生能力要求从「会建模/会写数值代码」转向「会设计协议、会构造评测集、会写清边界」。
- **选题匹配要换尺子**：适合工程化、协议设计、写作与论证能力强的学生；**不适合**想做模型训练/算法创新的学生（文中 `Suggested: 定位为可运行的教学/科研原型与过程证据` 已暗示这一点）。

**可伸缩性很好**：下限是「规则 Agent + 结构化工件 + 埋点冲突 + 录制回放」，笔记本即可完成；上限可加 RAG 条款依据、类型化冲突推理、量化对照实验，够支撑一篇扎实论文。

## 八、可直接发给学生的一块补丁（把「可解释」落到实处）

以下内容可直接作为开题报告「研究内容（3）+ 实验设计」的补充条款，用来把 5.1–5.5 五个硬伤一次补掉。

**① 工件 schema（所有 Agent 输出必须落盘，不得只存在对话里）**

```
artifact = {
  task_id, role, artifact_id, version, parent_version,
  params: [ { key, unit, value, range:[low,high], source_role, clause_ref } ],
  rationale,            // 依据：条款号 / 检索片段 / 规则编号
  created_at, llm_meta  // model, version, temperature, seed, prompt_hash
}
```

**② 冲突类型化（解释 = 命中规则 + 双方证据，不是模型自述）**

| 编号 | 类型 | 判定条件 |
|---|---|---|
| C1 | 同键异值 | 同一 `key` 被不同角色给出不同 `value`，且超出约定容差 |
| C2 | 区间不相交 | 两角色对同一参数的 `range` 交集为空 |
| C3 | 条款互斥 | 双方 `clause_ref` 指向互斥标准条款（条款互斥表由人工预置） |
| C4 | 口径/单位不一致 | `unit` 或 `key` 语义不同却未换算，先报「待定项」而非冲突 |

**③ 相似提示**：对 `params` 做字段 Jaccard 或参数向量距离，Top-k 返回，附「命中字段 + 双方依据」构成解释。

**④ 解释输出模板（可直接写进验收）**

```
冲突 C2 @ 参数 T_kiln
  热工角色: [1350, 1400]   依据 H-07
  标准角色: [≤ 1300]      依据 S-03
  判定: 交集为空 → 命中规则 C2
  处置: 交人工确认（确认 / 驳回 / 批注），不设仲裁 Agent
```

**⑤ 评测指标（对照实验的判据）**

| 指标 | 定义 |
|---|---|
| 冲突发现率 | 检出预置冲突数 / 预置冲突总数（按 C1/C2/C3 分列） |
| 误报率 | 非预置冲突被报出的条数 / 总报出条数 |
| 人工负担 | 人工修改次数、确认回合数、端到端耗时 |
| 提示采纳率 | 人工采纳的可解释提示数 / 提示总数 |
| 重跑一致率 | 同输入重跑，冲突集合与对照报告一致的比例 |

对照公平性：同样例、同基座模型、同 token/回合预算，只变「多角色协同 / 单 Agent 串行 / 纯人工模板」三种编排。

**⑥ 可复现与兜底**：`temperature=0` + 固定 seed；每回合 JSONL 落盘；`replay/` 目录存一次真实运行的完整 fixture；README 提供 `run`（在线）与 `replay`（离线，走 `mock_llm`）两条命令，二者都必须跑通主路径。

**⑦ 样例最小规格**：每套含任务书、4 类角色工件模板、≥12 条埋点冲突（C1/C2/C3 各 ≥4）、≥6 组相似方案对、`golden.json` 标准答案。2 套即可满足阻断项 ④，3 套用于泛化说明。
